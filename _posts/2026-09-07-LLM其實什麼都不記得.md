跟 AI 聊了半小時，它記得你叫什麼、記得你貼過的那段程式碼、記得你說你是寫 PHP 的。

但模型其實一句都沒記住。

<!-- more -->

## 每次呼叫都是全新的

實際去打一次 LLM 的 API 就會發現，它單純到有點無聊：你丟一包文字進去，它算完吐一包文字出來，結束。

那個模型不是一個「一直跑著的程式」，比較接近一個純函數。同樣的輸入進去，出來的東西就差不多。它身上沒有任何一個地方可以放「剛剛那個人說他叫 York」。

寫 PHP 的對這個模式應該很熟。php-fpm 那個 worker 也是跑完就把記憶體清光，下一個請求進來當作什麼都沒發生過。LLM 就是同一件事，只是那個「跑完就忘」的東西貴很多。

## 那對話為什麼是連貫的

因為每一次都把整段歷史重送一遍。

你以為你送出去的是「那第二種寫法呢？」，實際上送出去的是從第一句開始的整份逐字稿：系統設定、你問的第一題、它的回答、你的追問、它的回答⋯⋯最後才接上「那第二種寫法呢？」。

模型看到的是一整份劇本，然後接著往下寫。它不是「想起來」你剛剛問了什麼，是當場「讀到」你剛剛問了什麼，而且每一次都重讀一遍。

所以嚴格講，你並不是在跟它對話。你是每次拿一份越來越長的劇本，交給一個徹底失憶的演員，請他接下一句。

## 這解釋了很多日常現象

**為什麼對話越長越慢、越貴。** 因為你每次真的都把前面全部重傳一次，它也真的每次都重讀一次。第五十輪你只打了一個「好」，背後可能是幾萬字的輸入。

**為什麼它會「忘記」你十分鐘前講的話。** 上下文有長度上限，滿了之後前面的就會被截掉或壓縮。那不是忘記，是那段根本沒被送進去，它連看都沒看到。

**為什麼卡住的時候開新對話反而順了。** 因為髒掉的上下文清乾淨了。它前面答錯一次，那個錯誤答案就一直留在劇本裡被反覆重讀，越讀越歪。這跟重開機解決問題的道理意外地接近。

## 那「記憶」功能是誰做的

現在很多產品都有記憶了，會記得你的職業、你的習慣、你手上的專案。

那不是模型記住的，模型還是一樣什麼都不記得。是外面有一層東西幫你把這些抓出來、存進資料庫，下次你開新對話的時候，安靜地塞進最前面。

所以模型依然是每次讀一份全新的劇本，只是這份劇本開頭多了一段「這個人是後端工程師，寫 PHP，喜歡簡短的回答」。

我覺得這件事有意思的地方在於，它跟我們把 session 從本機檔案搬去 Redis，根本是同一個動作：狀態不放在處理請求的那個東西身上，放到外面一個大家都查得到的地方，要用的時候再撈進來。

換句話說，AI 的記憶不是什麼模型能力，是一個非常傳統的後端功能。

## 那 prompt caching 呢

既然每次都要重讀，重複的部分能不能不要重算？可以，這就是 prompt caching 在做的事。

它快取的是「前面那一大段一模一樣的內容算到一半的結果」，下次同樣的開頭直接接續，省時間也省錢。

但這不代表模型記得你。快取是服務端加的一層優化，模型本身照樣無狀態——就像你在應用前面擺了一台 Redis，並不會讓你的 PHP 變成有狀態的。

## 最後

理解這件事最實際的好處，是你會開始用對的方式看待它的行為。

它「忘記」不是它笨，是你沒送進去。它前後矛盾不是它在唬爛，是它讀到的那份劇本裡本來就有矛盾。它今天突然變聰明也不是它學會了，是這次的上下文比較乾淨。

模型什麼都不記得。所有的記憶，都是外面的人幫它記的。
